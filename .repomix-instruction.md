# Правила проекта (выжимка из AGENTS.md)

Этот бандл — снимок репозитория крипто-приложения. Перед работой с кодом
учитывай правила ниже; полная версия — в `AGENTS.md` в корне репозитория.

## Стек

- TypeScript ~6.0 (strict), Node.js 22+
- Vue 3.5 (`<script setup>` + Composition API), Vuetify 4.2, VueUse 15, vue-i18n 11
- Тулчейн Vite+ 1.2.0 (`vp` CLI): Vite/Rolldown, Vitest 5, Oxlint, Oxfmt
- Пакетный менеджер npm, `package-lock.json` в репозитории

## Команды

```bash
npm run dev          # vp dev, порт 3000, strictPort
npm run build        # type-check + build-only параллельно
npm test             # unit-тесты (обходной скрипт для Windows)
npm run lint         # Oxlint через vp lint
npm run format       # Oxfmt через vp fmt
npm run type-check   # vue-tsc --build (project references)
npm run knip         # поиск мёртвого кода, должен оставаться чистым
npm run context      # основной контекстный бандл (.agentic/context.md)
```

**Важно:** `npm test` запускает `scripts/run-vitest.mjs` — обходник для Windows
(двойная загрузка ESM). Не заменять на `vp test` или `vitest` напрямую.

## Архитектура и правило зависимостей

```text
src/
├── agent/            # WebMCP-реестр инструментов, LLM-клиент
├── components/       # ai/, layout/, workspace/
├── composables/      # useTheme, useLocale, useTour
├── crypto/           # чистые Web Crypto-провайдеры (без Vue, без i18n)
├── domain/           # каталог алгоритмов, модель формы
├── i18n/locales/     # ru.ts, en.ts
└── plugins/          # настройка Vuetify
```

Правило зависимостей строго сверху вниз: `components → domain/crypto`;
`agent/` может импортировать только `crypto`/`domain`; слой `crypto` никогда
не импортирует Vue; `composables` не зависят от `components`.

## Валидация перед завершением задачи

```bash
npm run format:check
npm run lint
npm run type-check
npm test
```

Не ослаблять ассерты, не удалять тесты ради зелёного прогона. Ошибка линтера,
форматирования или типов чинится в той же задаче.

## Ключевые правила кода

- TypeScript strict: не добавлять `any`, не лечить ошибки через `as unknown as`.
- Любая пользовательская строка — в оба словаря `src/i18n/locales/ru.ts` и
  `src/i18n/locales/en.ts`; хардкод текста в компонентах запрещён.
- Новое поведение в `crypto/` или `agent/` требует round-trip теста
  (зашифровать → расшифровать, подписать → проверить).
- Схемы WebMCP-инструментов живут только в `src/agent/toolRegistry.ts`.
- Весь тулчейн настраивается в `vite.config.mts`; не создавать `.eslintrc`,
  `.prettierrc`, отдельные `vitest.config.ts`.
- Не коммитить ключи, токены и `.env`-файлы.
