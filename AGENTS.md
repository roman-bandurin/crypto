# AGENTS.md

Правила для кодинг-агентов (Zoo Code, Cursor, Cline и аналоги), работающих в этом
репозитории. Для веб-агентов, которые обращаются к опубликованному сайту, см.
[`public/AGENTS.md`](public/AGENTS.md) — это другой документ с другой аудиторией.

Для grep-поиска по полному тексту исходников есть автогенерируемый
скилл-справочник (см. раздел 11).

## 1. Что это за проект

Одностраничное Vue-приложение: браузерная реализация криптоалгоритмов
(шифрование/подпись, дайджесты, генерация ключей) плюс встроенный AI-чат с
WebMCP-инструментами. Статика, без бэкенда; деплой на GitHub Pages.

## 2. Стек и требования

| Слой              | Технология                                                     |
| ----------------- | -------------------------------------------------------------- |
| Язык              | TypeScript ~6.0 (strict), Node.js 22+                          |
| Фреймворк         | Vue 3.5 (`<script setup>` + Composition API)                   |
| UI                | Vuetify 4.2, VueUse 15, vue-i18n 11                            |
| Тулчейн           | Vite+ 1.2.0 (`vp` CLI): Vite/Rolldown, Vitest 5, Oxlint, Oxfmt |
| Тесты             | Vitest 5 + `@vue/test-utils` + fast-check, окружение happy-dom |
| Пакетный менеджер | npm, `package-lock.json` в репозитории                         |

## 3. Команды: встроенные инструменты против скриптов

**Это главное правило Vite+.** Встроенная команда и npm-скрипт с тем же именем —
разные вещи: скрипты не могут перекрыть built-ins.

| Команда                                     | Что запускает                                          |
| ------------------------------------------- | ------------------------------------------------------ |
| `vp dev`, `vp build`, `vp test`, `vp check` | встроенные инструменты Vite+                           |
| `vp run <name>`                             | скрипт из `package.json` или task из `vite.config.mts` |
| `vp install`, `vp add`, `vp remove`         | управление пакетами выбранным `packageManager`         |

Команды проекта ([`package.json`](package.json)):

```bash
npm run dev          # vp dev, порт 3000, strictPort
npm run build        # type-check + build-only параллельно
npm run build-only   # vp build
npm run preview      # vp preview
npm run type-check   # vue-tsc --build (project references)
npm test             # unit-тесты (обходной скрипт для Windows, см. ниже)
npm run test:watch
npm run lint         # vp lint . --tsconfig=./tsconfig.json (Oxlint)
npm run lint:fix
npm run format       # vp fmt . (Oxfmt)
npm run format:check
npm run knip         # поиск мёртвого кода, должен оставаться чистым
npm run context      # сборка контекстного бандла (см. раздел 9)
```

### Почему `npm test` запускает скрипт-обходник

[`scripts/run-vitest.mjs`](scripts/run-vitest.mjs) нужен из-за Windows: пакет
`vitest` в этом проекте — алиас на версию Vite+, и прямой запуск через `.bin`
приводит к двойной загрузке ESM. Обходник канонизирует регистр пути и запускает
`vitest.mjs` напрямую. **Не «оптимизируйте» его, заменяя на `vp test` или
`vitest` напрямую.**

## 4. Валидация перед завершением задачи

Обязательный минимум перед тем, как считать работу законченной:

```bash
npm run format:check   # или vp fmt --fix, если формат нужно поправить
npm run lint
npm run type-check
npm test
```

`npm run build` — дополнительно, если менялась сборка, `base`, алиасы или
конфиг. `npm run knip` — если добавлялись или удалялись зависимости, файлы,
экспортируемые символы.

Правила:

- Не ослаблять ассерты, не удалять тесты и не подкручивать пороги ради зелёного
  прогона. Если проверка не проходит — чинить причину или явно сообщить о ней.
- Ошибка линтера, форматирования или типов — не «оставить на потом», а исправить
  в той же задаче.
- Не коммитить и не пушить без прямой просьбы пользователя.

## 5. Архитектура и правило зависимостей

```text
src/
├── agent/            # WebMCP-реестр инструментов, LLM-клиент, настройки AI
├── components/
│   ├── ai/           # плавающий AI-чат (v-bottom-sheet / v-dialog)
│   ├── layout/       # AppLayout: app bar, переключатели темы и языка, FAB
│   └── workspace/    # CryptoWorkspace — форма криптоопераций
├── composables/      # useTheme, useLocale, useTour
├── crypto/           # чистые Web Crypto-провайдеры (без Vue, без i18n)
├── domain/           # каталог алгоритмов, модель формы (refs + rules)
├── i18n/locales/     # ru.ts, en.ts
└── plugins/          # настройка Vuetify
```

**Правило зависимостей строго сверху вниз:** `components → domain/crypto`;
`agent/` может импортировать только `crypto`/`domain`; слой `crypto` никогда не
импортирует Vue; `composables` не зависят от `components`. Нарушение этой лестницы
ломает тестируемость, поэтому проверяй себя до добавления нового импорта.

## 6. Правила кода

- **Типы:** TypeScript strict. Не добавлять `any`, не «лечить» ошибки типов через
  `as unknown as`; новый публичный API — с явными типами.
- **i18n:** любая пользовательская строка добавляется в **оба** словаря
  [`src/i18n/locales/ru.ts`](src/i18n/locales/ru.ts) и
  [`src/i18n/locales/en.ts`](src/i18n/locales/en.ts). Хардкод текста в компонентах
  запрещён.
- **Тесты:** файлы `*.spec.ts` в `src/__tests__/`. Новое поведение в `crypto/` или
  `agent/` требует round-trip теста (зашифровать → расшифровать, подписать →
  проверить), ориентир — `crypto-workspace.spec.ts`.
- **WebMCP:** схемы всех инструментов живут только в
  [`src/agent/toolRegistry.ts`](src/agent/toolRegistry.ts); не регистрировать
  инструменты в других местах; обработчики остаются клиентскими, read-only и
  идемпотентными.
- **Конфиг:** весь тулчейн настраивается в [`vite.config.mts`](vite.config.mts)
  (блоки `lint`, `fmt`, `test`, `staged`). Не создавать `.eslintrc`, `.prettierrc`,
  отдельные `vitest.config.ts`.

## 7. Как работать с контекстом

- Дерево файлов проекта уже доступно из окружения. **Не вызывай `read_file` ради
  разведки** — сначала `codebase_search`/`search_files`, потом точечное чтение
  нужного фрагмента.
- За одну задачу — не больше 4–6 файлов; суммарно не больше 10–12. Массовое
  чтение (например, оба словаря локализации или весь набор тестов) переполняет
  контекст и приводит к сбоям провайдера.
- Для полного обзора репозитория есть готовые бандлы: `npm run context`
  (раздел 9) для Zoo Code с гарантией размера, `npm run repomix` (раздел 11)
  для ad-hoc снимков и передачи в внешние чаты.
- Не читай и не индексируй мусор: `.cursor/**`, `.roo/**`, `.vscode/**`,
  `.agentic/**`, содержимое `node_modules`.
- История рабочего дерева (2026-10-16): каталоги `plans/` и `docs/` перемещены
  из репозитория, корневой `env.d.ts` удалён (дублировал `src/env.d.ts`) —
  не восстанавливать и не искать их.

## 8. Безопасность и секреты

- Не коммитить ключи, токены и `.env`-файлы; в бандлы контекста они не попадают
  (см. раздел 9).
- Соблюдать рабочее дерево: перед началом осмотрить изменённые файлы, не затирать
  чужую и несвязанную работу.
- Деструктивные операции (удаление, перезапись, перемещение) — только после явного
  подтверждения и с резервной копией.

## 9. Контекстный бандл

```bash
npm run context                      # сборка в .agentic/context.md
npm run context -- --stdout          # вывод в консоль без записи файла
```

Скрипт [`scripts/build-context.mjs`](scripts/build-context.mjs) — тонкая обёртка
над repomix: repomix выбирает файлы (gitignore, whitelist из `--include`,
отсечение бинарников, security check), а скрипт применяет жёсткие лимиты размера
и собирает предсказуемый markdown-бандл с манифестом для передачи в другой агент
или в чат без доступа к репозиторию.

**Use Case:**

- **Основной workflow для Zoo Code** — гарантированное влезание в контекстное окно.
- Жёсткие лимиты: 120 КБ на файл, 400 КБ на весь бандл (repomix умеет только
  падать по `--token-budget`, а здесь бандл обрезается до гарантированного объёма).
- Whitelist источников — `INCLUDED_DIRS`/`INCLUDED_FILES` в скрипте
  (`src/`, `scripts/`, `public/` и корневые конфиги).
- Фиксированный путь вывода: [`.agentic/context.md`](.agentic/context.md).

Альтернатива для ad-hoc снимков без ограничений размера — repomix (см. раздел 11).

## 10. Публичный контракт сайта

Каталог [`public/`](public/) — это не статика «на выброс», а публикуемый
агентный контракт: `AGENTS.md`, `llms.txt`, `llms-full.txt`, `index.md`,
`sitemap.md`, `sitemap.xml`, `openapi.json`, `agent-permissions.json`,
`robots.txt` и манифесты в `.well-known/`. Ссылки на них перечислены в
[`index.html`](index.html). Изменение этих файлов меняет то, что видят веб-агенты,
поэтому правки должны быть осознанными, а канонический URL сайта — обновляться
через `VITE_SITE_URL` (см. `scripts/rewrite-site-urls.mjs`).

Правило скрипта самопроверки этого слоя — `scripts/check-agent-ready.mjs`.

## 11. Repomix: ad-hoc снимки репозитория

Помимо основного бандла (`npm run context`, раздел 9) в проекте настроен
[repomix](https://repomix.com) — упаковка репозитория в один файл для чатов и
агентов без доступа к коду.

```bash
npm run repomix        # сборка repomix-output.md по repomix.config.json
npx repomix --stdout   # вывод в консоль без записи файла
```

Конфигурация — [`repomix.config.json`](repomix.config.json):

- формат `markdown` (читаемее XML для небольшого проекта);
- приоритизация через `topFilesLength`/`topFilesPrefixes`: сначала
  [`AGENTS.md`](AGENTS.md), конфиги тулчейна, затем `src/domain/`, `src/crypto/`,
  `src/agent/toolRegistry.ts`, потом UI и локализация;
- инструкция [`.repomix-instruction.md`](.repomix-instruction.md) — краткая
  выжимка правил этого файла предшествует коду в бандле;
- security check включён: секреты в бандл не попадут.

**Use Case:**

- Ad-hoc снимки для передачи в чаты без доступа к репозиторию (ChatGPT, Claude веб).
- MCP-интеграция (Cursor, Cline, Claude Desktop) — чтение через инструмент `pack_codebase`.
- **НЕ ГАРАНТИРУЕТ размер бандла** — может превысить 400 КБ и убить контекст Zoo Code.
- Приоритизация (`topFilesPrefixes`) полезна, когда важен порядок файлов в бандле.

### Скилл-справочник кодовой базы

Команда `npm run repomix:skill` (обёртка над `repomix generate_skill`) собирает
автогенерируемый справочник в `.claude/skills/crypto-project-reference/`:

- `SKILL.md` — точка входа с инструкцией по поиску;
- `references/project-structure.md` — дерево каталогов со счётчиками строк;
- `references/files.md` — полный текст всех файлов (искать по `## File: <path>`);
- `references/tech-stacks.md` — языки и зависимости.

Справочник **не содержит правил проекта** — только код и структуру. Он полезен,
когда нужен grep по полному тексту исходников; правила всегда брать отсюда.
Перегенерация — вручную после крупных изменений (дерево файлов в окружении
агента обычно достаточнее).

### Сравнение с build-context.mjs (раздел 9)

| Аспект             | build-context.mjs              | repomix                     |
| ------------------ | ------------------------------ | --------------------------- |
| **Назначение**     | Основной workflow для Zoo Code | Ad-hoc снимки и MCP-клиенты |
| **Лимиты размера** | ✅ 120 КБ/файл, 400 КБ/бандл   | ❌ Нет гарантий             |
| **Приоритизация**  | ❌ Нет                         | ✅ topFilesPrefixes         |
| **Runtime-флаги**  | ❌ Нет                         | ➖ Настройка в конфиге      |
| **MCP-сервер**     | ❌ Нет                         | ✅ Есть                     |
| **Инструкции**     | ❌ Нет                         | ✅ .repomix-instruction.md  |

**Правило выбора:** для Zoo Code всегда `npm run context`; repomix — для внешних
чатов, MCP-клиентов и когда нужна приоритизация файлов.

Правила использования repomix:

- Вывод (`repomix-output.md`) в репозиторий не коммитится (см. `.gitignore`).
- **Code compress (минификация) не использовать** — убивает читаемость кода,
  комментарии и осмысленные имена важнее экономии токенов.
- **Автогенерацию `AGENTS.md` из repomix не применять** — этот файл поддерживается
  вручную и содержит правила, которые автогенератор не выведет; автогенерация
  даёт только справочник кода (скилл выше), а не правила.
